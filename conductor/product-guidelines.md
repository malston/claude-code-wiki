# Product Guidelines

## Voice and Tone

Dry, precise, direct. No filler, no hedging, no superlatives. Show with code, config, and commands rather than describing in prose. See [STYLE-GUIDE.md](../STYLE-GUIDE.md) for the full enforcement list.

## Design Principles

1. **Accuracy over speed** -- verify technical details against source code and documentation before publishing. If you can't confirm a claim, don't make it.
2. **Show don't tell** -- use code blocks, configuration snippets, and command examples. Prose supports the examples, not the other way around.
3. **No filler** -- every sentence carries information. Cut rhetorical padding, superlative adjectives, and contrastive reframes.
4. **Depth over breadth** -- go deep on fewer topics rather than shallow coverage of many. Each article should be the definitive reference for its subject.
5. **Keep it current** -- update articles when Claude Code changes. Mark version-specific details explicitly.
6. **Enterprise-ready** -- content supports organizational adoption: security, compliance, cost management, phased rollout.

## Content Structure

Each article follows a consistent structure:

- Executive summary with key facts table at top
- Table of contents
- ASCII diagrams for architecture concepts
- Decision matrices and flowcharts for guidance
- Practical examples with real file structures
- Best practices section
- References to official docs at bottom

## Style Authority

[STYLE-GUIDE.md](../STYLE-GUIDE.md) is the source of truth for all content writing rules. Key prohibitions: contrastive reframes, superlative filler, rhetorical triplet lists, hedged bold sandwiches, relative product-timeline phrasing, and internal implementation type names in user-facing prose.
